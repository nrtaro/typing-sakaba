# 混雑時の配膳テンポ

ブランチ：`codex/combo-procurement-balance`。ミス猶予・素材バランス調整に続く追加修正。

## 歩行速度

女将と娘の両方に、店内にいる客（入店中・注文待ち・食事中）の人数で同じ倍率を適用。入口の行列と退店演出中の客は数えない。

| 店内の客数 | 基本歩速に対する倍率 |
|---|---|
| 0〜2人 | 1倍（従来の歩速） |
| 3人 | 1.25倍 |
| 4人 | 1.5倍 |
| 5人 | 1.75倍 |
| 6人 | 2倍 |
| 7人 | 2.25倍 |
| 8人 | 2.5倍 |

往路・復路とも適用。客数が変わっても急に速度が跳ねないよう、時定数0.18秒で目標の歩速へ近づける。歩行コマは引き続き実際に歩いた距離で進めるため、移動速度と足運びが対応する。配膳の手渡しアニメーションのフレームと再生速度は維持。

## 配膳担当

以前は席の偶数・奇数だけで担当を決めていたため、空いている家族がいてももう一人に料理が積み上がる場合があった。現在は担当の待ち件数が多ければ、空いている方へ振り分ける。同数なら元の担当順。調達中の家族には渡さず、出発時の未配膳料理の引き継ぎも維持する。

## 検証

- 夜開始時の8席に料理を同時に完成させ、実素材の配膳アニメーション長と実際の入退店・待ち処理を含めて1/60秒ずつ進めた。
- 最後の料理の受け渡し：変更前14.98秒 → 変更後8.98秒（約40%短縮）。これは固定シード・8件同時完成の比較で、全状況で同じ秒数になるものではない。
- 料理8件をすべて失わず届け、売上の計上は8件のまま。受け渡し前に食事時間を消費しない。
- 女将・娘とも2人→4人→8人で実際の移動距離が増えること、空席が増えると滑らかに通常速度へ戻ることを確認。
- 同じ担当席が続いても2人へ分散。片方が調達中で同じ担当に連続注文が入る場合も、取りこぼさず届ける。
