## 手元で確かめる

必要なもの：Node.js 24.15.0以降の24系、または26以降、npm（テストで `node:sqlite` とjsdomを使います）。

```powershell
npm ci
if (-not (Test-Path -LiteralPath .dev.vars)) { Copy-Item .dev.vars.example .dev.vars }
```

`.dev.vars` の `RANKING_IP_SALT` をランダムな長い値に変えてください。これはIPを保存用のハッシュにするための秘密値で、公開リポジトリには入れません。すでに `.dev.vars` がある場合は上書きせず、この項目だけ追加します。

```powershell
npm run build
npm run db:local
npm run dev:worker
```

`http://localhost:8787/` でビルドしたゲームとAPIが動きます。ここで使うD1は **このパソコンの `.wrangler/` 内だけ** です。仮のdatabase_idのままでも手元では確かめられます。

画面を直しながら確かめる場合は、別のターミナルで `npm run dev` を実行し、`http://localhost:5280/?slot=ranking-check` を開きます。`/api` は8787のWorkerへ転送します。Workerを止めているとランキングはエラー表示になりますが、通常営業とひがわり営業は遊べます。

確認の流れ：

1. 「はじめる」→「ひがわり」→難易度→今日のお題で、上位5人が表示されることを確認。
2. 営業を終え、Enterまたは `namae` で「なまえをいれる」を選ぶ。
3. 日本語で名前を入力。変換の確定Enterでは送られず、その次のEnterで送信されることを確認。
4. Escまたは「やめる」で閉じた場合は送られないことを確認。
5. 送信後に「今日○位／○人中」を確認。同じ端末の低い記録では、以前のベストが順位に使われる。
6. Workerを止め、上位の取得・送信に失敗しても遊べて、端末の記録が残ることを確認。

確認用の保存枠を片付ける場合は、ブラウザの開発者ツールで末尾 `.ranking-check` の `lastorder2.*` キーだけを消してください。普段の保存枠は消さないでください。

## 本番の準備（了承後）

1. 本番D1の `database_id` は `wrangler.jsonc` に設定済み。
2. 本番のテーブル作成は、ユーザーの了承を得てから次を実行。

   ```powershell
   npx wrangler d1 migrations apply typing-sakaba --remote
   ```

3. 本番用の十分長いランダムな秘密値を、次のコマンドで登録。値をチャットやコミットへ書く必要はありません。

   ```powershell
   npx wrangler secret put RANKING_IP_SALT
   ```

4. ゲームの確認後、ユーザーから反映の依頼があった場合にのみmainへマージ・push。

秘密値が未設定の場合、送信APIは503を返します。D1が未設定・利用できない場合もランキングだけエラー表示になり、静的ファイルは従来どおり配信します。

## 決めた細部

- 日付×難易度×端末IDで1つのベストを保存。上回ったときだけ、名前と成績を一緒に更新します。同点の名前変更はしません。
- 同点は同順位（1位・1位・3位）。同点内は、その点数を先に保存した人を先に表示し、さらに同じ時刻なら端末IDで順序を固定します。
- 名前は文字幅と前後の空白を整え、1〜10コードポイントで確認。制御文字・表示を紛らわしくする文字・簡単な禁止語を拒否します。名前はキャンバス上の文字として描き、HTMLとして扱いません。
- JSTの今日の記録を受け付けます。0時から5分未満は前日も受け付けます。開店時の日付で最後まで遊ぶ既存の動きは維持します。長い一時停止のあとなど、期限を過ぎた記録は端末にだけ残ります。
- 1つのIPまたは端末から直近10分に10回まで。低い記録や同点の送信も数えます。不正な入力は保存しません。送信履歴と保存をD1の1トランザクションにまとめ、同時送信でも制限を守ります。
- IPは秘密値を使うHMAC-SHA-256で保存。生のIPをDBに残しません。送信回数用の履歴は10分経過後、次の送信時に消します。ベストのIPハッシュは成績と一緒に保持します。
- 成績は売上上限（やさしい6万／ふつう10万／むずかしい12万円）、150皿以下、最大コンボが皿数以下、怒って帰った客300人以下、正確さ0〜1、打鍵/秒0〜15で確認します。料理を出しているのにコンボや正しい打鍵が0の記録も拒否します。売上は、報告された最大コンボによる倍率と、その日のお題の「ひでんの」「宴会」の回数からも上限を確認します。これは明らかに不自然な送信を止めるための確認です。改ざんを完全に防ぐ再現確認・Turnstileは段階6です。
- 通信は8秒で打ち切り、送れなかった記録は結果画面から再送できます。通信後に別の画面へ移っていたら、その返答で次の営業を変更しません。
- 同じ端末IDを含むGETの応答はキャッシュせず、APIには端末ID・IPハッシュを出しません。
- 上位と自分の順位はSQLで計算し、実SQLiteを通すテストで確認します。別の純粋関数へ同じ順位計算を重複実装しません。

## 段階6：記録のやり直し・Turnstile・Xへのポスト（2026-11-07）

### 何が変わったか
- **1/60秒刻みの営業**：営業は画面の更新の間隔にかかわらず、1/60秒ずつ進む（`src/core/session.ts` の `PlaySession`）。打ったキーは「何刻み目に何を押したか」として記録する（数字＝前の入力からの刻み数、続く1文字＝キー。Backspace=B、スペース=S、Enter=E）。
- **配膳の係をゲームの計算側へ**：女将と看板娘が料理を運び、お客が食べ始める時刻は、以前は描画側が決めていた。サーバーで同じ営業を再現できるよう `src/core/crew.ts` に移した（描画はこの位置を読むだけ）。
- **サーバーでのやり直し**：送信には乱数の種・入力の記録・仕込みの振り分けが付く。Worker は記録どおりに営業をやり直し（`worker/verify.ts`）、成績が一致したときだけ、やり直して出た数字を保存する。一致しなければ 400「遊んだ記録と成績が一致しませんでした」。
- **Turnstile**：`TURNSTILE_SITE_KEY` と `TURNSTILE_SECRET` の両方があるときだけ、名前入力に Cloudflare の確認を出し、確認の印がない送信を 403 で断る。どちらかがないときは今までどおり（確認なし）。ゲームは `/api/daily/config` で公開キーを受け取る。
- **Xにポスト**：結果画面に「Xにポスト」（`posuto`）。X のポスト画面を新しいタブで開くだけで、投稿は遊ぶ人が決める。ひがわりは日付・難易度・売上・順位（送ったあと）・お題、通常営業は難易度・売上・ランク。

### 処理時間（大事）
- 3分の営業のやり直しは、手元のパソコンで 1回 約40〜70ms かかる（`tests/replay.test.ts` に目安を出している）。
- **Cloudflare Workers の無料プランは、1回の処理で使える計算時間が約10ms**。無料プランのままだと、送信がときどき（または毎回）処理時間切れで失敗するおそれがある。**有料プラン（Workers Paid）なら 30秒まで使えるので問題ない。**
- 無料プランのまま公開する場合の逃げ道：変数 `RANKING_REPLAY` を `off` にすると、やり直しを省き、段階5と同じ数字の確認だけで受け付ける（Turnstile は使える）。
- **2026-11-07：アカウントは無料プラン**。`wrangler.jsonc` の `vars` で `RANKING_REPLAY` を `off` にしてある。有料プランにしたら、この設定を消せば（または `on` にすれば）やり直しの確認が始まる。

### Turnstile を有効にする手順（ユーザーが行う）
1. Cloudflare のダッシュボード → Turnstile → 「ウィジェットを追加」。名前は「タイピング酒場」など、ホスト名に `typing-sakaba.nr-lab.workers.dev` を入れ、モードは「マネージド」。
2. 表示された **サイトキー**（公開してよい）と **シークレットキー**（秘密）を控える。
3. サイトキーは `wrangler.jsonc` の `vars` に `TURNSTILE_SITE_KEY` として書く（公開してよい値）。シークレットキーは `npx wrangler secret put TURNSTILE_SECRET` で登録する（入力を求められたら貼り付ける。このコマンドはすぐに公開版へ反映される）。
4. 手元で試すときは、Cloudflare の試験用キー（サイトキー `1x00000000000000000000AA`、シークレット `1x0000000000000000000000000000000AA`、いつも成功する）を `.dev.vars` に入れる。

### 記録を残して、あとから手元で確かめる（無料プラン向け）
- 送信のたびのやり直しは止めているので、かわりに **遊んだ記録（乱数の種・入力の記録・仕込みの振り分け）を自己ベストと一緒に `scores` に残す**（`migrations/0002_score_records.sql` で `seed`・`record`・`prep` の列を追加）。
- 上位の記録は、手元のパソコンでやり直して確かめる。データベースは読むだけで、書き換えない。
  ```bash
  npm run audit                                   # 今日の3難易度の上位20人（本番）
  npm run audit -- --date 2026-11-08 --top 50     # 日付・人数を指定
  npm run audit -- --difficulty hard              # 難易度を指定
  npm run audit -- --local                        # 手元（wrangler dev）のデータベース
  ```
  結果は「一致」「一致しない（理由）」「記録なし（段階6より前の送信）」。一致しない記録があれば、消すためのコマンドを表示する（実行はしない。内容を確かめてから手で実行する）。
- **公開の順番に注意**：新しいコードは追加した列に書き込むので、**先に本番のデータベースへ `0002` を当ててから**、コードを公開する（逆にすると、送信がすべて失敗する）。
  ```bash
  npx wrangler d1 migrations apply typing-sakaba --remote
  ```
  列を足すだけなので、今の公開版（段階5）はそのまま動き続ける。
- 手元での確認（2026-11-07）：手元の Worker に本物の記録と売上を500円増やした記録を送り、`npm run audit -- --local` で本物は「一致」、書き換えは「一致しない」、段階6より前の送信は「記録なし」と出ることを確かめた。
