# sakuraiレビュー修正 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. No implementation delegation; verify each task before proceeding.

**Goal:** ユーザー指定の順に保存、入力の可読性、方針説明と集計を修正する。
**Architecture:** 繁盛記の保存に世代付きチェックポイントと未受領効果を同じキーで記録し、Web Locks下で反映する。UIは保存成功を待ち、失敗は再試行、競合は最新状態への復帰を案内する。掛け声は厨房領域へ配置し、IME検知では明示的な再開が必要な一時停止を行う。方針の数値は変えず、説明・助言・推計表示の定義を合わせる。
**Tech Stack:** 既存TypeScript/Vite/Vitest、localStorage、Web Locks。追加依存なし。
**Spec:** docs/sakurai-review-stage9.md とユーザーの修正順指定。

## Global Constraints
- 対象は繁盛記を含む typing-sakaba-build（build-run-mode）。cwd側の導入変更には触らない。
- 旧セーブを読めるままにし、既存の獲得・装備・通貨・周回を保持する。
- ゲームの難易度・価格・報酬量・方針倍率は変更しない。
- 各項目は期待する修正後のテストを先に書き、失敗→実装→成功を確認する。

## Review Focus
- 一部キーだけの保存失敗と復旧後の報酬・実績の再付与。
- 同時/古いタブの書込と、中断・次の日・完走の境界。
- 全8席の入力と掛け声、IMEと既存一時停止・調達の整合。
- 未解放方針、交換した主力、支援型・直接売上型の振り返り。
- 既存テスト、通常/日替わりの保存・ランキング再現、型チェックとビルド。

## Rulings
- 既に合意した総合レビューとユーザーの実装指示を設計・範囲の承認として使う。新しい企画ヒアリングは行わない。
- 主力は「ラン全期間の直接売上の推計が最大の方針」と定義し、支援効果まで厳密な円換算にしない。推計の対象範囲を表示する。
- 対応ブラウザではWeb Locksを使う。保存の安全性が確保できない場合は古い進行を書かず案内し、通常営業は継続可能にする。

## 実施台帳
- 元ツリーへ直接編集せず、ハッシュ付き隔離コピーで実装。反映直前に元ファイルとの一致を照合する。
- 保存の再現テストは4件RED→GREEN。IME停止・全日程の主力・おもてなし閾値もRED→GREEN。
- Ruling: 支援効果は円換算を増やさず、直接売上推計の対象外と画面で明記する。
- 最終レビューの描画例外と退出経路の指摘は、実際のkana参照例外と退出不可のテストをREDにしてから修正。
- Ruling: 保存非対応・拒否の際には未保存分を説明した退出を用意し、通常営業を利用可能にする。
- フォント文字索引テストの不足5文字を生成スクリプトで更新。
