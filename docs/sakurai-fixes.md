# sakurai総合レビューの修正記録

対象: `typing-sakaba-build` / `build-run-mode`、基準コミット `78fe72b21e73885b42e59aa0d657161e4a95fe01`。2026-11-14。

ユーザー指定の順で、保存 → 演出とIME → 方針説明と振り返りを修正した。営業の難易度、方針倍率、報酬額は変更していない。

## 修正内容

1. 繁盛記の進行を保存する際は、読み込んだ保存内容と現在値を照合し、Web Locksで複数タブの書き込みを直列化する。古い進行なら上書きせず、最新状態の入口へ戻す。同期の保存APIも失敗と競合を例外で通知する。
2. 進行と未受領の実績・報酬を同じlocalStorageの値へ先に保存し、個々の付与に成功してから受領済みにする。途中の失敗は再試行でき、再起動時は繁盛記を開くと復旧する。報酬の受領IDは通常営業の直近200件の履歴から独立して保持する。読み取り拒否も空のコレクションで上書きしない。
3. 保存が済むまで次へ進ませず、保存中・再試行の専用画面を表示する。保存できないときは「保存を再試行」または「保存せず戻る」を選べる。後者は未保存分が消える旨を明記する。
4. 通常営業でも掛け声を厨房内へ収め、注文の文字を隠さない。
5. IME入力（compositionstart / isComposing / Process / 非ASCII文字）を検出したら営業を一時停止する。半角英数へ切り替え、Enterを押して再開する。単に英字を打っただけでは再開しない。
6. おもてなしに「2秒以上」と、ついでの皿には付かない条件を明記する。未解放方針を次の候補として助言しない。主力は入れ替え済みの方針も含めた全日程の直接売上推計で選ぶ。
7. 「いちばん働いた方針」を「直接売上の推計（上位3つ）」へ改め、補給・客数・コンボ進行などの間接効果を含まない旨を表示する。直接売上が未計上でも「働いていない」とは扱わない。過去のレベルを保存していない方針に、仮のLv1ツールチップを付けない。

## 限界

- Web Locks対応のセキュアコンテキスト（HTTPSまたはlocalhost）が繁盛記の安全な保存に必要。非対応・保存禁止では繁盛記の進行を止める。「保存せず戻る」で通常営業へ戻れる。
- Chromeの専用プロファイルと人工的なCompositionEventで確認する。Windowsの実IMEを人が切り替える操作と、Safari/Firefox等での実機確認は未実施。
- 保存APIが最初のチェックポイントを書けない場合、ブラウザを閉じれば未保存分は残らない。既に失われた過去の報酬を推測で復元する機能は追加していない。
- 書き込みの排他は今回の保存経路を使うタブ間で有効。旧バージョンのタブは再読み込みが必要。通常営業やふくびき等、別機能全体の複数タブトランザクション化は今回の範囲外。
- 貢献の円表示は発動タグへの配分による推計を維持した。支援効果を厳密な円へ換算した値ではない。

コミット・公開・デプロイは行わない。旧作業フォルダーLast-Orderの初回導入に関する既存変更は保持する。
